# AuxMemo v2 与提示词增强 设计 + 页面功能设计

> 定位：[`cache-hit-mechanism.md`](cache-hit-mechanism.md) 的 **M4 落地**。
> 前置事实：M1（三区模型）、M2（指纹链 + chain_ok）、M3（BoundaryCompactor，手动 + 用户边界自动）已上线；M1 的遥测面板已能量出稳态命中率。
> 本文档覆盖两件事：**AuxMemo 完整版**（L1/L2 精确缓存 + 分层账本）与**提示词增强**（第二个白名单调用 + Composer 页面功能），以及两者的页面功能设计。

---

## 1. 范围与原则（继承自总设计）

- **只服务白名单幂等调用**。一个调用可进 AuxMemo 当且仅当：输入完全决定输出、无副作用、失败可安全重放、输出不驱动文件编辑 / shell 执行。agent 主循环轮次永远禁入。
- **键侧归一，载荷恒等**：归一化只作用于 key 计算，绝不触碰出站 payload（辅助调用的 payload 本身就是构包结果，不由缓存层改写）。
- **不做语义缓存**：精确键匹配，差一个字节就是 miss。
- **跨工作区禁止共享**：workspaceNS 进 key、进目录。

### 1.1 白名单调用面（本版两个）

| kind | 触发 | 输入 | 输出 | 幂等性说明 |
|------|------|------|------|-----------|
| `title` | 首轮对话结束后自动 | 用户首条 + 助手首条（各截 600 字） | ≤12 字标题 | 纯文本进纯文本出，无世界状态 |
| `enhance` | 用户在 Composer 点击「优化」 | 草稿全文（截 4000 字） | 优化后的提示词 | 同上；输出仅替换草稿文本，不进入模型上下文、不驱动工具 |

边界压缩（summarize）**不进**白名单：其输入依赖"当前完整 transcript + 上次摘要"这一世界状态，虽然可入 key，但输出会替换后续全部请求的前缀——缓存它省的钱有限、复放旧摘要的风险却真实存在。

## 2. 组件设计

```
auxmemo.rs
  ├─ key 计算    key = SHA-256("v2|" + kind + "|" + model + "|" + endpoint
  │                        + "|" + SCHEMA_VER + "|" + input + "|" + workspaceNS)
  │              workspaceNS = 工作区路径的 SHA-256 前 16 hex；无工作区 = "global"
  │              （endpoint = provider base_url，防同模型不同网关误命中）
  │
  ├─ L1  进程内有界 LRU（容量 128 条 / 2 MiB 文本上限，先到先清）
  │      值 = { text, model, in_tok, out_tok, cost_usd }  ← 命中时可回填账本的"节省"列
  │
  ├─ L2  磁盘缓存：appData/auxcache/<workspaceNS>/<key-hex>.bin
  │      · 静态加密：payload = SHA-256-CTR 流加密（key 文件 appData/auxcache.key，
  │        32 字节随机，首启生成，权限 0600 语义）
  │      · 文件头 magic "AUX1"，解不开 / 解出非法 JSON → 删除该条目（按 miss 处理）
  │      · 有界：单工作区目录 ≤ 8 MiB，超限按 mtime 淘汰最旧
  │      · L1 miss → L2 → 都 miss 才发真实调用；任何一层命中即短路
  │
  └─ 账本  appData/aux-ledger.jsonl（追加写，进程内互斥）
         每行 = { ts, kind, model, origin: "l1"|"l2"|"miss",
                  input_tokens, output_tokens, billed_usd, saved_usd }
         · miss: billed = 真实调用成本（provider usage × 定价），saved = 0
         · l1/l2: billed = 0，saved = 入库时记录的 cost_usd
         · 主循环遥测（RequestStat）不含辅助调用 —— 两本账永不混流
```

### 2.1 读写路径

```
get(kind, model, endpoint, input, ns)
  → L1 命中 ⇒ 返回 (text, stats, "l1")，账本记 l1 行
  → L2 命中（解密 + 校验）⇒ 回填 L1，账本记 l2 行
  → miss ⇒ 调用方发真实请求（complete_once，带 usage 解析）⇒
     put() 写 L1 + L2，账本记 miss 行（billed=真实成本）
```

- **put 失败静默**：磁盘错误只影响缓存效果，不影响功能；账本写失败打日志，不中断。
- **完整流程的调用方职责**：auxmemo 不发请求。`commands.rs` 负责 resolve provider、调用 `chat::complete_once`（扩展为返回 usage）、把结果与成本喂回 `put`。缓存层保持纯存储。

### 2.2 静态加密说明

L2 落盘内容可能包含用户草稿与对话片段（视为敏感）。采用 SHA-256 计数器模式流加密（`keystream[i] = SHA256(key || counter)`，XOR 明文）：不加第三方依赖、语义上满足"at-rest 加密"（防的是同机其他用户/同步盘扫盘，不是防持有密钥的本地进程——后者对任何本地加密都不成立，密钥就在同一目录）。

## 3. 页面功能设计 A：Composer「提示词增强」

### 3.1 交互流

```
[textarea 有草稿且会话已绑定模型]
   └─ foot 栏出现「✨ 优化」按钮（busy / 无模型时隐藏）
        └─ 点击 → 按钮进入 loading（转圈、不可重复点）
             ├─ origin = l1 / l2 → 立即返回，面板标注「来自本地缓存（未产生 API 调用）」
             └─ origin = miss → 走真实调用（数秒），面板标注「由 <model> 生成」
        └─ textarea 上方浮出增强面板：
             ┌──────────────────────────────────────────┐
             │ ✨ 优化后的提示词      来源: 本地缓存 L2    │
             │ ┌──────────────────────────────────────┐ │
             │ │ （增强结果，只读 textarea，最高 160px）│ │
             │ └──────────────────────────────────────┘ │
             │              [放弃]  [采用并替换草稿]       │
             └──────────────────────────────────────────┘
        └─ 采用 → 草稿被替换（原草稿不保留，Ctrl+Z 由 textarea 原生支持）
        └─ 放弃 / Esc → 面板关闭，草稿原样
```

### 3.2 状态与边界

| 情况 | 行为 |
|------|------|
| 会话无绑定模型 / Provider 未启用 | 按钮隐藏（`canEnhance = sessionId && binding && !busy`） |
| 草稿为空 | 按钮隐藏（与发送按钮同一判据） |
| 草稿 > 4000 字 | 后端截断到 4000 字，面板不提示（增强结果本就是重写，不会更长） |
| 调用失败 | toast error，面板不出现，按钮恢复 |
| 增强中用户继续编辑草稿 | 允许；采用时**整体替换**（所见即所得的是增强结果，不是 diff 合并） |
| 附件 / 技能 chip | 不参与增强——只增强 textarea 里的草稿文本 |

### 3.3 设计要点

- **增强结果永远不直接发送**：必须经过「采用」这步显式确认——辅助调用的输出不得绕过用户进入模型上下文（与总设计"输出不驱动执行"同源的界面纪律）。
- 同一草稿第二次点击必然命中缓存（键 = 草稿字节）——这是把"精确缓存"变成用户可感知功能的方式：面板上的「本地缓存」徽标即命中率的具象化。
- 缓存键含 model + endpoint：换了模型再点「优化」，会走真实调用拿到新风格的结果，符合直觉。

## 4. 页面功能设计 B：Telemetry「辅助调用精确缓存」区块

挂在现有遥测页底部（请求账本之后），与主循环遥测**视觉分组**——两张账本，两种性质。

### 4.1 汇总卡片（4 张）

| 卡片 | 值 | 说明 |
|------|-----|------|
| 辅助调用次数 | N | 账本行数 |
| 精确命中率 | (l1+l2)/N | 只在白名单调用上统计——这是总设计定义的"精确命中率"指标 |
| 节省成本（估算） | Σ saved_usd | 命中时按入库成本计 |
| 实际计费 | Σ billed_usd | miss 轮的真实成本 |

### 4.2 账本表格（最近 50 条，新在上）

| 列 | 内容 |
|----|------|
| 时间 | ts |
| 类型 | 标题生成 / 提示词增强 |
| 模型 | model |
| 来源 | L1 / L2 / 未命中（未命中红色、L1/L2 绿色） |
| 输入 / 输出 | token 数（命中行 = 入库时记录的量） |
| 计费 | billed_usd |
| 节省 | saved_usd（仅命中行有值） |

### 4.3 读数说明（随卡片附一段）

> 此账本只统计白名单幂等调用（标题生成、提示词增强）。agent 主循环的每轮请求记录在上面的请求账本中，两类账本永不分摊——命中行 billed=0 是精确缓存的直接证据。

## 5. 风险对照

| 风险 | 对策 |
|------|------|
| 旧决策打新世界 | 白名单四条标准 + 主循环禁入（编译期：auxmemo 无任何 ChatMessage / 请求体类型依赖） |
| 跨工作区泄漏 | workspaceNS 进 key 且作目录名；不同 NS 物理不同目录 |
| 磁盘缓存明文 | SHA-256-CTR 静态加密 + magic 校验，损坏即删 |
| 计费失真 | origin/billed/saved 三字段入账，与主循环遥测分册 |
| L2 无界膨胀 | 8 MiB 上限 + mtime 淘汰 |
| 增强输出直接进上下文 | 界面强制「采用」确认；后端 enhance 结果只回传，不落会话消息 |

## 6. 验收（CI 可测）

1. 键确定性：同 (kind, model, endpoint, input, ns) 键恒等；任一因子变化键必变（单测）。
2. L1 容量淘汰：插入超容量条目后最旧条目 miss（单测）。
3. L2 往返：put → 新进程句柄 get（模拟重启，清 L1）→ 命中且文本一致（单测）。
4. 加密落盘：磁盘文件不含明文子串（单测）。
5. 工作区隔离：ns=A 写入，ns=B 查同输入 → miss（单测）。
6. 账本分层：命中行 billed=0、saved>0；miss 行相反（单测）。
7. typecheck + cargo test 通过。

## 7. 明确不做的事

- 不缓存边界压缩摘要（理由见 1.1）；
- 不做 embedding / repo map 缓存（本仓库无对应调用面，等调用面出现再入白名单）；
- 不做 L2 的 TTL（条目 8 MiB 有界 + mtime 淘汰已够；模型下线导致的陈旧命中无害——它只是多省一次调用）；
- 不给 AuxMemo 暴露开关（同前缀纪律：关掉等于主动多花钱）。
