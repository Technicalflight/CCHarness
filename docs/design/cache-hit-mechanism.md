# CCHarness 缓存命中机制设计

> 目标：**命中率最高、风险最低**。
> 结论先行：主力放在请求侧——制造前缀可缓存性，让 provider 侧前缀缓存在**每个请求**上命中（这是长会话省钱的大头）；响应侧只保留一个作用域收窄的精确缓存，服务幂等辅助调用。不做语义缓存。

---

## 0. 两个指标，别混为一谈

| 指标 | 定义 | 来源 | 本设计的目标 |
|------|------|------|--------------|
| 前缀命中率 | `cached_input_tokens / total_input_tokens`（单请求） | provider 回传的 usage 字段（DeepSeek: `prompt_cache_hit_tokens`/`miss`；OpenAI 兼容: `prompt_tokens_details.cached_tokens`） | 稳态 ≥ 95%，零意外全 miss |
| 精确命中率 | 辅助调用被本地缓存接管的比率 | 本地缓存账本 | 只在白名单调用上统计，不追求全局数字 |

前缀命中省的是**每个请求**的重复前缀 token（缓存价通常约 1/10）；精确命中省的是偶发的整次调用。主循环的钱几乎全在前者。

---

## 1. 请求分区模型（核心）

每个出站请求按字节顺序分三个区：

```
┌────────────────────────────────────────────────────────┐
│ Zone S 冻结区：system prompt（会话内一次写定，永不改字节） │
├────────────────────────────────────────────────────────┤
│ Zone H 历史区：append-only。已发送的内容原字节入史，       │
│              任何组件不得改写、重排、重序列化               │
├────────────────────────────────────────────────────────┤
│ Zone T 尾区：本轮新增的动态状态块 + 最新用户消息           │
│              （下一轮整体落入 H，成为稳定前缀的一部分）      │
└────────────────────────────────────────────────────────┘
```

三条铁律：

1. **发送即 immutable**：凡进入 Zone H 的字节永不变化。动态状态（todo、git 摘要、记忆提示）的更新方式是"尾部追加新块"，旧版本留在历史里当便宜的前缀，最新版本永远在 Zone T。一个块入场付一次全价，之后所有请求按缓存价复用。
2. **Zone T 块准入门槛**：新增一个尾区块前必须回答——这信息是否已在消息历史里？能否做到"语义不变则字节不变"？量化分档（如 token 用量的 10% 桶、低/中/高三档）只允许在**序列化时**做，禁止在构包层做任何依赖浮点/时间的精细渲染。
3. **载荷恒等，键侧归一**：本地任何缓存键/统计的规范化，只作用于键的计算，**绝不触碰出站 payload**。JSON 序列化固定键序、无时间戳、无 locale 相关格式化、数字格式确定。

### 前缀纪元（epoch）

以下事件开启新纪元（命中率重新爬坡，属预期重建，非事故）：模型切换、provider/endpoint 切换、压缩发生、system prompt 版本升级。每个会话维护 `epochId`，遥测按纪元分段统计。

## 2. 组件设计

```
PromptAssembler ──┬─ Zone S 构建（会话首turn，之后引用不变字节）
                  ├─ Zone H 管理（append-only buffer，存已序列化字节而非对象）
                  └─ Zone T 组装（本轮动态块 + 用户消息）

RequestFreezer ── 每轮构建一次出站请求对象，deep-freeze；
                  所有中间件（重试/降级/投机侧路）只允许 copy-on-write，
                  侧路请求必须剥离主路径专属标志位

DigestChain ───── D_i = H(D_{i-1} || 本轮新增字节)；O(增量) 维护
                  每请求记录 (digest, 前缀字节长度)

PrefixTelemetry ─ 读 provider usage 的缓存 token 字段；
                  对照 DigestChain：本地链未断而 provider 报 miss
                  → 二分定位分歧（params/endpoint/模型不符，或 provider 逐出）
                  会话/纪元两级汇总，产出命中率曲线

BoundaryCompactor（唯一允许改写 Zone H 的组件）
                  仅在用户边界（新一轮用户消息到来前、上一轮完全结束后）触发；
                  阶梯式：不压 → 轻剪枝 → 摘要重建，命中即止；
                  重建 = 摘要 + 有界保留尾（仅最近一条用户消息，上限 2 万 token）；
                  可见 transcript 永不删改——压缩只影响发出去的上下文

AuxMemo（响应侧精确缓存，作用域收窄）
                  只服务白名单幂等调用：标题生成、prompt 增强、embedding、
                  repo map 再生成、测试/基准回放
                  key = H(model, endpoint, params, 归一化输入, workspaceNS, schemaVer)
                  L1 进程内 LRU（有界）；L2 按工作区分目录的磁盘缓存（有界，静态加密）
                  重放记录 origin=cache、billed=0，单独入账
                  禁止缓存含 tool_use 的 agent 轮；禁止跨工作区共享
```

### 白名单的判定标准（AuxMemo 准入）

一个调用可进 AuxMemo 当且仅当全部满足：输入完全决定输出（无世界状态依赖，或依赖已完整进入 key）；无副作用；失败可安全重放；输出不驱动文件编辑/shell 执行。**agent 主循环的轮次四条全不满足，永远不进。**

## 3. 风险对照表

| 风险 | 来源 | 本设计的对策 |
|------|------|--------------|
| 前缀字节意外翻转 | 中间件原地改请求、侧路重入双写 | RequestFreezer + copy-on-write 纪律；侧路剥标志 |
| 动态状态抖动 | 每轮变化的状态被写进前部 | 三区模型：状态只追加在尾部 |
| 压缩打断缓存 | turn 中途重写历史 | BoundaryCompactor 只在用户边界动 H；turn 中只置 pending |
| 旧决策打新世界 | 响应缓存重放带 tool_use 的轮次 | AuxMemo 白名单四条标准，主循环禁入 |
| 语义误命中 | 嵌入相似 ≠ 意图相同 | 不做语义缓存（连降级提示都不做，保持简单） |
| 数据跨项目泄漏 | 磁盘缓存共享 | workspaceNS 隔离 + 按工作区分目录 + 静态加密 |
| 计费失真 | 重放 token=0 却无记录 | origin/billed 字段入账，仪表盘分层展示 |
| 静默劣化 | 没人知道命中率掉了 | DigestChain + provider usage 对照，分歧告警定位到字节 |

## 4. 观测与验收

- **每请求**记录：前缀字节长度、DigestChain 断点、provider 命中/未命中 token。
- **每纪元**汇总：命中率曲线、重建尖峰位置与幅度。
- 验收标准（CI 可测）：
  1. 脚本化 N 轮会话，断言每轮前缀字节 = 上一轮前缀 + 纯追加（字节级测试）；
  2. 稳态（压缩间隔内）前缀命中率 ≥ 95%；
  3. 重建尖峰只出现在用户边界/纪元切换点，幅度有界且与会话长度解耦；
  4. 任一 provider miss 在本地链未断时必须能定位到原因分类。

---

## 5. 实施顺序

1. **M1 三区模型 + RequestFreezer + 遥测**：先把命中率量出来，不动其他。
2. **M2 DigestChain + 字节稳定性守卫**：CI 加字节级回归测试。
3. **M3 BoundaryCompactor**：阶梯压缩 + 纪元标记。
4. **M4 AuxMemo**：白名单辅助调用接入，账本分层。

M1 的遥测先行是刻意的：没有基线数字之前，任何"优化"都无法证明自己有效。

---

## 6. 明确不做的事

- 不做语义缓存（L3），包括"只提示不回放"的降级版——收益配不上复杂度；
- 不在主循环做任何响应重放；
- 不做跨会话/跨工作区的响应或前缀共享；
- 不让任何归一化逻辑接触出站字节；
- 不给用户暴露前缀调参开关（预算从模型窗口推导，机制永远在线——关掉它等于主动多花钱）。
